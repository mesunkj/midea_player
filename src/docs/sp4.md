# 📋 規格修飾書：失敗圖檔手動標註與跨 Model 批次 Check-out 機制

## 1. 獨立的「手動修正」進入按鍵（非綁定於掃描流程）

* **需求變更**：修正原本必須在「掃描完成後」才能進入標註畫面的限制。
* **實作細節**：
* 在主介面（例如 ConfigView 或主選單）提供一個**獨立的常駐按鈕**（例如：「檢視/修正失敗圖檔」或「手動標註工具」）。
* 只要資料庫（`viewport_db.json`）中存在任何 `unrecognized`（失敗）的檔案，該按鈕即保持可點擊狀態，使用者可隨時點擊進入手動標註畫面，不需重新執行全域掃描。



---

## 2. 靈活的標註互動方式（點擊 vs 拖曳 + 自動比例縮放）

* **需求變更**：改善標註體驗，支援「滑鼠拖曳」或「兩點點擊」的互動方式，並自動將座標轉換為原圖比例的 `viewport`。
* **實作細節**：
* **互動方式**：
1. 支援傳統滑鼠拖曳（允許任意方向，如右上至左下、左上至右下等）。
2. 支援兩點依序點擊（點擊第一點作為起點，點擊第二點作為終點）。


* **視覺回饋**：在操作過程中（拖曳或點擊第一點後移動滑鼠），即時渲染出 `#00ff88` 的虛線矩形選取框（dashed block）供使用者預覽。
* **座標比例計算**：當使用者按下「確定」時，系統必須自動依據**圖片的原始尺寸比例**進行換算與縮放，產出正確且標準化的正規化座標（`x, y, w, h`，範圍介於 0~1 之間）。



---

## 3. 失敗圖檔的「Check-out（直接維持原圖）」機制

* **需求變更**：針對某些辨識失敗但實際上不需要縮放、希望直接採用原圖的圖片，提供一鍵 Check-out 功能。
* **實作細節**：
* 在標註介面中新增一個 **「Check-out / 維持原圖」** 的專屬按鈕。
* 當使用者點擊時，系統自動將該圖片的 Viewport 設定為**原圖尺寸**（即 `x: 0, y: 0, w: 1, h: 1`），並將其狀態從失敗（`unrecognized`）轉為正常或手動確認狀態，同時自失敗清單中移除。



---

## 4. 相同檔名全域 Check-out（跨 Model 批次套用）

* **需求變更**：結合前面提到的「跨 Model 檔名相同」特性，當某個檔案被執行 Check-out 時，同主題或全域目錄下**所有相同檔名**的圖片應同步被 Check-out。
* **實作細節**：
* 當使用者對某個失敗圖片執行 **Check-out** 時：
1. 系統擷取該檔案的「檔名」（例如 `001.jpg`）。
2. 自動搜尋資料庫中所有分佈在不同 Model 底下、但**檔名相同**的圖片實例。
3. 批次將這些相同檔名的圖片全部設定為原圖 Viewport（`x: 0, y: 0, w: 1, h: 1`），並一併自失敗清單中移除，避免使用者需要重複手動處理多個 Model 裡的同一張圖。
