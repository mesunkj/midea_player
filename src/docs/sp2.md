# 📋 新功能規格書：失敗圖檔手動標註與修正系統 (Manual Viewport Annotation Tool)

## 1. 任務背景與目標

承接先前的 `viewport_db.json` 掃描機制，當系統在掃描目錄時發生人臉辨識失敗的狀況，會被歸類為 `unrecognized` (🟥) 並記錄其 `failedPath`。
本功能旨在建立一個**前端互動介面與 Python 後端輔助系統**，讓使用者能夠讀取這些失敗的圖檔，手動框選正確的檢視區塊（Viewport），更新資料庫，並將檔案從失敗清單中移除（移至垃圾桶或更新狀態）。

---

## 2. 後端與資料提取需求 (Python / Main Process)

* **提取失敗路徑**：撰寫 Python 腳本或主程序邏輯，從 `viewport_db.json`（或傳入的資料檔案）中讀取所有 `failedFiles`（即 `unrecognized` 狀態的完整路徑 `full path`）。
* **載入圖檔**：根據提取出的 `full path` 讀取對應的圖檔，並提供給前端渲染顯示進行手動校正。

---

## 3. 前端互動介面與功能需求 (Renderer UI / Interactive Canvas)

### 3.1 圖片檢視與虛線輔助框

* 當使用者介面載入失敗圖檔時，提供一個圖片預覽畫布（Canvas / Container）。
* **即時預覽（虛線 Block）**：在使用者進行滑鼠拖曳標註的過程中，前端必須即時渲染出一個**虛線矩形選取框（dashed block）**，讓使用者能清楚看出目前選取的檢視區域範圍。

### 3.2 互動標註邏輯（支援多種拖曳方向）

* 使用者透過滑鼠互動指定矩形的 **Viewport**。
* 支援任意方向的拖曳起訖點：
* 例如：由右上至左下、左上至右下、或是由右下至左上等。
* 系統需能自動計算並記錄該矩形的正確座標與範圍（轉換為正規化的 `x, y, w, h` 矩形 Viewport）。



### 3.3 操作控制項（Undo 與 Confirm）

* **復原 (Undo)**：允許使用者取消當前選取，清除虛線框並重新選擇。
* **確認 (Confirm)**：使用者確認框選範圍後點擊送出。

### 3.4 資料庫與檔案狀態更新

當使用者點擊「確認」後，系統需執行以下動作：

1. 更新 `viewport_db.json` 中該檔案的狀態（將原本的 `unrecognized` 修正為手動標註的新 Viewport，狀態可轉為 `zoomed` 或自訂的手動標註狀態）。
2. 將該檔案從失敗清單 (`failedFiles`) 中移除。
3. **歸檔處理**：將該檔案從原本的失敗區移除，並妥善處理（例如移動至指定的垃圾桶/備份區域，或依據實際的需求將其從失敗佇列中排除）。
